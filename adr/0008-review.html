1. Why

List + chat is not enough for ops questions:

  • Age / last activity / closed time
  • Model + workspace binding
  • Token burn (reported + est)
  • Tool mix and errors
  • Markdown path for copy/paste

Leverage existing data

  • sessions row index
  • session_events kinds, tokens, latency
  • Live registry busy / dirty
  • MD front matter fallback when limp

2. UI (locked)

Header ⓘ + list context menu · modal · explicit open only · Close session with confirm.

  • Errors truncated to 500 chars; system agents allowed

3. API

GET /api/sessions/{id}/info

→ {
  session: { id, title, status, busy, dirty, times, model, workspace, md_path, … },
  usage:   { event_count, tokens_*_reported/est, tool_calls, errors, blob_count, latency_* },
  tools:   [ { name, calls, errors }, … ],
  recent_events: [ { seq, ts, kind, tool_name, tokens_*, latency_ms, error }, … ],  // last 30
  source: "db" | "memory" | "markdown",
  partial: false
}

Limp / no DB → metadata only, partial: true, empty usage/timeline (no fake tokens).

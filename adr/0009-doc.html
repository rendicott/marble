Context

Agents often produce artifacts meant for humans outside the chat transcript: research notes, runbooks, status pages, incident timelines. Today those either sit in the workspace (mixed with project files) or only in session Markdown.

mpub (“Marble publish”) gives every session a first-class tool to publish content into the harness memory tree and have it served immediately from the same HTTP server as the Marble UI:

user: Do research on foo and mpub it
agent: … research …
agent: mpub(slug="foo-research", content="…")
→ http://127.0.0.1:8080/mpub/foo-research

Requirements implied by the product sketch:

  1. Tool available to every agent (built-in, not MCP-only).
  2. Storage under --memory (harness-owned, not the workspace jail).
  3. HTTP serve path under the Marble listen address: /mpub/<slug>.
  4. Durable across restarts (files on disk).

Decision

  1. Built-in tools: mpub_publish, mpub_list, mpub_get, mpub_unpublish (Q1, Q11).
  2. Store under $MEMORY/mpub/<slug>/ (jailed; not workspace).
  3. Primary format: HTML; markdown also supported and rendered to a simple HTML page when served (Q2, Q3).
  4. HTTP (before SPA catch-all): GET /mpub index, GET /mpub/{slug}, optional raw (Q7, Q12).
  5. Default overwrite on publish; optional if_exists=fail; no append (Q4, Q13).
  6. Agent must supply slug in the tool call (Q8).
  7. Max body 2 MiB; HTML allowed without sanitizer (XSS documented) (Q5, Q6).
  8. Meta records session_id when available (Q9).
  9. Tool result URL: http://127.0.0.1{port}/mpub/{slug} from --addr (Q14).
  10. Works in limp (disk + HTTP only) (Q15). No SPA browser in v1 (Q10).
  11. Unauthenticated same as UI; document exposure of /mpub/* (updated: see visibility — private pages are admin-only when OAuth is on).

Tool surface (v1 — locked)

Tool Purpose

mpub_publish inputs

Field Notes
slug Required URL segment; agent-chosen

content_type Default text/html; also text/markdown, text/plain

Output:

{
  "ok": true,
  "slug": "foo-research",
  "path": "/mpub/foo-research",
  "url": "http://127.0.0.1:8080/mpub/foo-research",
  "bytes": 4096
}

url host: derive from request Host when available; for tools use listen addr / 127.0.0.1 + --addr port (open Q).

Slug rules (proposed)

  • Allowed: [a-z0-9]([a-z0-9-]*[a-z0-9])? length 1–64
  • Lowercase; reject .., /, empty, reserved (api, static, .)
  • Collision: overwrite replaces; create fails if exists

On-disk layout (detail)

$MEMORY/mpub/<slug>/
  meta.json
  content.html        # primary when content_type=text/html
  content.md          # when markdown
  content.txt         # when plain

HTTP serving

Content type Response
text/html Serve as HTML (no sanitizer v1; XSS risk documented — local trust)
text/markdown Render simple HTML page (title + styled body) for browser reading
text/plain text/plain; charset=utf-8 (or wrap in minimal HTML — implementer)

Index GET /mpub: simple HTML list (title, slug, updated_at, link).

Security

Risk Mitigation
Path escape under mpub Strict slug + resolve under $MEMORY/mpub
XSS via published HTML Open Q: raw HTML only for trusted local; or strip scripts
Data exfil / open port Same as dashboard; document exposure
Huge pubs Max body size (e.g. 2 MiB)
Secrets in pubs Agent responsibility; optional future redaction

Relationship to other surfaces

Surface Role
Workspace tools Project files the agent edits
Memory knowledge (memory_write) Intentional long-term notes for agent recall
mpub Human-facing published pages on the harness web server
Session MD Chat transcript ground truth

mpub is not a substitute for memory_write (agent memory search) or session transcripts.

Consequences

Positive

  • Clean “share this result as a page” workflow.
  • Artifacts survive session close and process restart.
  • No extra process — reuses marble-harness HTTP.

Trade-offs

  • Publishes on the same unauthenticated port as the UI.
  • Markdown rendering quality is basic unless we pull a library.
  • Naming collisions if many agents use generic slugs.

Risks

Risk Mitigation
Agent overwrites important pub if_exists=fail; operator unpublish
Disk fill 2 MiB cap + list/unpublish
XSS via published HTML Document; local/Tailscale trust only
Confused with workspace paths tool descriptions + $MEMORY/mpub tree

Out of scope

  • Multi-user ACLs / signed URLs
  • Version history / diffs of pubs
  • Full site generator / media galleries
  • SPA mpub browser (v1)
  • Nested slugs

Implementation order (after accept)

  1. internal/mpub store + slug validation + tests
  2. Tools: publish, list, get, unpublish
  3. HTTP GET /mpub + GET /mpub/{slug} (HTML primary; MD→HTML)
  4. Wire tools into registry; system prompt one-liner
  5. Simple MD→HTML template
  6. Health/About: mpub count or link
  7. Docs + example usage

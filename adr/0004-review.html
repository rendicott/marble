1. Goal

Give operators the same tree the agent tools use, without leaving Marble.

  • Browse, create, rename, delete
  • View/edit non-binary text
  • Upload / download / archive folders
  • Copy paths into chat

Out of scope

  • Browsing --memory
  • Git / LSP / multi-root IDE
  • Binary hex editor
  • Auth (inherits current open UI trust model)

5. API sketch

GET  /api/workspace
GET  /api/workspace/list?path=
GET  /api/workspace/read?path=
PUT  /api/workspace/write          {path, content}
POST /api/workspace/mkdir          {path}
POST /api/workspace/rename         {from, to}
DELETE /api/workspace?path=
GET  /api/workspace/download?path=
GET  /api/workspace/archive?path=  → application/gzip tar.gz
POST /api/workspace/upload?path=   multipart

Paths jailed to --workspace (shared helper with agent tools).

6. Security

  • Same trust model as today: unauthenticated UI ⇒ full workspace R/W if port is exposed
  • No symlink escape; no .. jailbreak
  • Caps on edit/upload/archive size (see questions)

7. Decisions Q5–Q18 (locked)

Q1–Q4 locked above. Recs still apply for the rest.

UX

Q5 Editor: textarea vs highlight library?
Rec: textarea v1 (no new deps).
Q6 Show dotfiles by default?
Rec: yes (sysadmin-friendly), with toggle to hide.
Q7 Delete non-empty folders?
Rec: yes with strong confirm.
Q8 New file → auto-open editor?
Rec: yes.
Q9 Mobile long-press for context menu?
Rec: yes (same as sessions).

Limits / API

Q10 Max editable size?
Rec: 1 MiB.
Q11 Max upload per file?
Rec: 50 MiB (stream to disk).
Q12 Overwrite policy?
Rec: upload conflict → confirm; Save overwrites open file.
Q13 Symlinks?
Rec: list; follow only if target stays in jail.
Q14 tar.gz caps?
Rec: ~200 MiB / 10k files — abort with error.
Q15 Huge file download?
Rec: stream; no extra cap.

Product

Q16 --workspace-readonly?
Rec: defer.
Q17 Audit deletes/uploads to SQLite?
Rec: defer.
Q18 Notify agent on operator edit?
Rec: no.

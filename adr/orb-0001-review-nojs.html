Questions

Already locked

Q0a LOCKED Brand / domain?
Decision: Canonical domain orbnet.app (apex portal, www→apex, api.orbnet.app, gw.orbnet.app).
Q0b LOCKED Envelope vs body?
Decision: Fan-out ≤2KB envelope everywhere; body stored once, GET on open, hard cap 1MB UTF-8. No 128KB vs 1MB fetch tiers. Bots default envelopes-only. Meter envelope count + body-fetch GB.

Product / positioning

Q1 Who is the first user?
Rec: First user is you + Marble (API-first, one private topic, desktop tray + optional ntfy for phone). Homelab/public later.
Q2 Hosted SaaS, self-host binary, or both from day one?
Rec: Hosted SaaS only in v1 (orbnet.app). Self-host binary is phase 3.
Q3 Compete with ntfy or integrate?
Rec: Do not compete as a ntfy clone. Optional BYO ntfy topic as a 2KB wakeup sink. Optional ntfy-compatible POST gateway on api.orbnet.app later.
Q4 Public topics: world can listen only, or unauthenticated publish like ntfy?
Rec: Public topics are listen-only. Only keyed publishers may POST. Topic URL is not a password.
Q5 Are paid topics (subscribers pay publishers) in v1?
Rec: No paid topics / subscriber marketplace in v1. Bill publishers for usage only (or free until it hurts).
Q6 Tone of clients?
Rec: Ops-terminal tone: dense markdown inbox, not chat bubbles, not consumer-calm marketing.

Message model

Q7 Attachments in v1? Inline images?
Rec: No attachments in v1. Markdown subset, no raw HTML. Images only as https links (client renders, server does not fetch).
Q8 Binary / JSON-only agent payloads vs markdown-only?
Rec: Markdown/text is the product. Optional YAML front matter (orb.agent.v1). JSON body allowed if Content-Type is application/json but still stored as the blob; not a second product.
Q9 Priority: ntfy 1–5 or silent/normal/urgent?
Rec: ntfy-style priority 1–5 on the envelope. Map to Android channels / iOS interruption later.
Q10 Retention defaults?
Rec: Free: 7d body retention private, 24h public. Envelope index 7d both. Tune with plan later.
Q11 Replay for humans vs bots — same topic?
Rec: Same topic. Humans and bots both get envelopes. Bots opt into body fetch / durable offsets. No separate topic type.
Q12 Threading / run_id grouping in UI?
Rec: v1 flat feed grouped only by topic. Optional client-side group by run_id if present. No threads-as-product.
Q13 Read receipts / delivery acks to publishers?
Rec: No read receipts in v1. Body-fetch logs are for metering/abuse, not shown to publishers.
Q14 Who writes the envelope preview?
Rec: Server truncates preview from title + first markdown lines to fit remaining envelope budget. Publisher cannot override with a longer preview.

Auth & keys

Q15 Verified email required, or GitHub OIDC enough?
Rec: Email magic link required to create topics. GitHub/Google OIDC optional in addition, not instead, until passkeys.
Q16 One key many topics, or topic-scoped only?
Rec: v1 keys are topic-scoped. Account-level admin key (orb_ak_) manages topics/keys but does not publish unless explicitly granted.
Q17 Subscriber API keys on public topics?
Rec: Anonymous OK for public subscribe. Optional subscriber key only for private/paid or for bots that want higher rate limits / durable cursor.
Q18 Invite link: one topic or org bundle?
Rec: Invite is single-topic. Org bundles are v1.5.
Q19 Stolen invite — unlimited devices?
Rec: Invite: max uses default 10, expiry 7d, cap 5 devices per grant. Owner can revoke.
Q20 Anonymous → billed account merge across devices?
Rec: Anonymous device key signs a merge to the new account; subscriptions unioned. Conflicts: account prefs win.

Clients & platforms

Q21 Client stack?
Rec: v1: web SPA/PWA + Tauri desktop (macOS/Linux first, Windows next). Phone: BYO ntfy until native. Flutter Android then iOS after Apple/Google accounts exist.
Q22 Linux tray — which desktops?
Rec: Linux: StatusNotifierItem / AppIndicator. GNOME: notifications still work if tray is hidden; document that.
Q23 macOS menu bar vs dock?
Rec: macOS: menu bar extra + optional dock. Default: menu bar, no dock bounce unless priority ≥4.
Q24 Signed/notarized installers in MVP?
Rec: MVP: unsigned/raw binaries + Homebrew-style script. Notarize when we have the Apple account.
Q25 Who owns Apple/Google developer accounts?
Rec: Operator’s personal Apple/Google accounts until a company exists. Don’t block desktop on store listings.
Q26 UnifiedPush / ntfy-as-distributor on Android?
Rec: No UnifiedPush in v1. FCM when we have an Android app. Until then ntfy distributor is the user’s problem.
Q27 Web portal as billing system of record for CLI-only users?
Rec: Yes — web portal is system of record for billing even if the user only uses CLI.

Notification policy

Q28 If Mac is unlocked, suppress phone?
Rec: No cross-device suppression in v1. Each device honors its own prefs. Presence is a later project.
Q29 Global DND vs per-topic mute vs publisher priority — who wins?
Rec: Subscriber always wins: global DND > per-topic mute > publisher priority (priority only affects how loud if not muted).
Q30 Can publishers mark un-muteable urgent?
Rec: No un-muteable urgent. Subscriber always sovereign, including security-ish pings.
Q31 Digest algorithm?
Rec: Digest = time bucket (hourly/daily) of envelopes, not a new body. Off by default.
Q32 Install ntfy for v0 phone push — BYO topic or Orb-hosted relay?
Rec: v0 humans may install ntfy and paste a topic URL into Orb (BYO). Orb-hosted ntfy relay is extra ops — skip until native apps.
Q33 Postcard / lock-screen contents?
Rec: Lock-screen postcard = title only (or title + 80 chars if user enables preview). Default title-only for private topics.

Architecture / infra

Q34 NATS on ECS vs Synadia Cloud vs skip broker?
Rec: Self-run NATS JetStream on ECS for envelopes (3-node) when we outgrow a single box. Spike may be Postgres LISTEN + Redis. Not Synadia Cloud on day one.
Q35 Single region which city?
Rec: us-west-2 unless operator is closer to us-east-1. Single region v1.
Q36 Isolate JetStream per tenant now?
Rec: No per-tenant JetStream accounts in v1. One stream with subject per topic id. Isolate later if noisy.
Q37 Max subscribers per topic in v1?
Rec: Soft cap 10k subscribers/topic in v1. Envelope fanout is cheap; don’t promise millions.
Q38 VPC / PrivateLink for enterprise agents?
Rec: No PrivateLink in v1.
Q39 IaC: Terraform or CDK? Existing AWS org?
Rec: Terraform. New AWS account orb-prod separate from personal junk.
Q40 Observability vendor?
Rec: CloudWatch + one Grafana Cloud or nothing fancy. OpenTelemetry traces on publish/fetch.

Billing & legal

Q41 Who is the legal entity charging cards?
Rec: No charges until a legal entity exists. Free caps only. Stripe later under that entity.
Q42 Free cap numbers?
Rec: Free: 3 public + 1 private topic, 10k envelopes/month, 2GB body-fetch, 1GB stored bodies.
Q43 Price points?
Rec: Defer price points until we have usage. No public pricing page in spike.
Q44 Data residency / EU region?
Rec: No EU region in v1. Disclose US processing in privacy policy.
Q45 E2E encrypt agent traces?
Rec: No E2E in v1. Server can read bodies. Optional E2E is phase 2.
Q46 Content moderation / CSAM if public markdown?
Rec: Public topics: ToS + abuse report + freeze. No image hosting reduces CSAM surface. Hash/report if we ever allow uploads.

Agent-specific

Q47 First-class MCP server for Orb?
Rec: Yes, a small MCP server (publish, list envelopes, fetch body) once HTTP API exists. Not a blocker for spike.
Q48 Bidirectional replies / agent.ask Accept-Deny?
Rec: v1 one-way. Human reply / agent.ask callbacks are v2 (auth on callback so a stolen notification cannot approve).
Q49 Schema registry or freeform markdown forever?
Rec: Encourage orb.agent.v1 front matter. No enforced schema registry in v1.
Q50 Agent feedback loops across topics?
Rec: X-Orb-Path hop list + max 8 hops. Drop publish if cycle detected. Document it.
Q51 Replace email/Telegram in Marble, or sit beside them?
Rec: Orb sits beside email/Telegram in Marble as another sink. Do not rip out existing channels in v1.
Q52 ntfy-compatible publish URL on api.orbnet.app?
Rec: Optional ntfy-compatible POST https://api.orbnet.app/ntfy/{topic} that maps to envelope+body. Nice-to-have after native API.

Ops / team

Q53 Who runs on-call?
Rec: Operator is on-call. No pager rotation. Best-effort SLA.
Q54 Budget ceiling first 90 days?
Rec: Keep first 90 days under a few hundred USD (single region, tiny RDS/Fargate). No Apple/Google fees until store apps.
Q55 Open source clients / server / neither?
Rec: Keep server+clients closed until there’s a product. Protocol/docs can be public later.
Q56 Success for a 6-week spike?
Rec: Success: Marble publishes to a private orbnet.app topic; Mac tray shows envelope; opening fetches markdown body; one publish key. Phone optional via BYO ntfy.

Harness inner loop

Center-out design for a Go harness: local OpenAI-compatible model (no API keys), a tool-calling agent loop, multi-session goroutines, and a real web chat portal — not a terminal-in-browser.

1. Context

Hermes / OpenClaw-class tools are heavy and their UIs fight the user. Marble starts from the center: one local model, a tight agent loop, three filesystem tools, and a simple multi-session web shell.

First model = OpenCode local config. Same endpoint and limits as ~/.config/opencode/opencode.jsonc (local-llama → Qwen3.5-122B-A10B-FP8. No keys required.

2. Decision

Ship a single Go binary that:

  • Hosts the web portal + JSON/SSE API
  • Runs independent session goroutines (isolated history)
  • Exposes shared tool implementations under a workspace jail
  • Enforces configurable context budget on every model call

Out of scope (later ADRs)

  • Auth / multi-user
  • Disk persistence
  • Summarization / memory
  • Shell, git, web, browser tools
  • MCP / plugins / TUI

3. Agent inner loop

user msg→ append history→ budget trim→ chat/completions + tools→ tool_calls?→ exec tools→ loop

If no tool calls: emit final assistant message and end the turn.

  • At most one in-flight turn per session (busy → reject / 409).
  • Max tool iterations per turn (default ~25).
  • Sessions share config + tool code only — never chat context.

4. First tools

All paths resolved under --workspace; escape outside root is rejected.

ToolPurposeKey inputs
file_read Read text file (optional line window) path, offset, limit
file_write Create / overwrite text file path, content
list_files List directory entries path, optional recursive
Large reads/results are truncated with an explicit marker so the model can re-request a smaller window.

5. Context limits (configurable)

Budget is inherent to the loop, not bolted on: budget = context_limit − max_output − context_reserve.

FlagDefaultRole
--base-url127.0.0.1:8000/v1OpenAI-compatible root
--modelQwen/Qwen3.5-122B-A10B-FP8Model id
--context-limit262144Total window
--max-output32768Generation cap per call
--context-reserve8192Tools/schema headroom
--workspace.FS tool root
--addr:8080Listen address

Trim policy (v1)

  1. Estimate tokens (approx OK: chars/4 or light tokenizer).
  2. If over budget, drop oldest non-system messages; never drop latest user turn.
  3. Truncate oversized tool payloads.
  4. No auto-summarization in v1 — fail closed if a single turn cannot fit.

8. Consequences & risks

Positive

  • Small, ownable Go center
  • No key plumbing for first model
  • Limits retargetable for other models
  • Real chat UI, multi-session isolation

Trade-offs / risks

  • Approx token counting until real tokenizer
  • No persistence / no auth in v1
  • Qwen reasoning vs content field quirks
  • Tailscale endpoint availability

9. Implementation order (post-accept)

  1. config + model client smoke test against local Qwen
  2. tools unit tests with temp workspace
  3. session agent loop without UI
  4. HTTP API + registry
  5. Embedded web portal + SSE
  6. Budget integration tests

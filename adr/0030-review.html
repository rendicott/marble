Agent-process presets & turn send-routing

Make call_agent_process (ADR-0014) explicit instead of prompt-mediated: named, host-detected presets (grok, opencode, claude, …) in Settings ⚙, plus a way to route a turn's prompt to a subprocess — via long-press/right-click send (one turn) or a session lock (subprocess-only).

Pain

The only way to use an external harness is to persuade the model to emit a tool call — free-form, skippable, and blind to what's installed.

TodayGap
Model must emit call_agent_process with a hand-written promptNo deterministic, operator-controlled trigger
agent_process.json drivers (grok/claude), hand-editedNo Settings UI, no presets, no new drivers without rebuild
Driver fails at fire time if binary missingNo host detection / version badge
"Run this session on Grok to save cost"No per-turn override, no session lock

Shape (proposed)

composer send
   ├─ normal click ───────────► normal Marble turn
   ├─ long-press / right-click ► preset chooser ─► TurnOpts.AgentPresetID (this turn only)
   └─ session locked ─────────► routes EVERY turn (unified selector: model OR detected preset)

routed turn:
   user message ─ wrap (preamble + cwd + msg)
     │
     ▼
agentproc.Manager  (preset P: driver · command · args · model)
     │  BG task · poll progress · stuck_hint
     ▼
Result ─ emitted VERBATIM as assistant message (no Marble model call)
Resolution order: turn override → session lock → normal Marble turn. Missing/disabled/not-detected preset ⇒ advisory + fall through.
Not in this ADR: streaming child stdout, resume/continue, auto model-vs-agent routing, remote agents, arbitrary shell presets, per-run cost metering.

Open questions

Use rec / pick an option / write custom. Export saves 0030-answers.json.

Q1Preset shape — generalize drivers → named presets?
Rec: presets: named bundles (driver + command + model + default_args + timeout). One preset per driver by default for back-compat.
Q2Preset storage
Rec: SQLite agent_presets (schema v4), like model_catalog; agent_process.json stays as global caps + first-run seed.
Q3Host detection
Rec: Resolve command + run --version probe; cache detected/version/path in the row. Startup warm + on-demand.
Q4Prompt wrapping for a routed turn
Rec: Wrap: short harness preamble + cwd + the user message verbatim.
Q5Result collection
Rec: Reuse agentproc.Manager BG task + poll + progress/stuck; fold Result as the turn's assistant message.
Q6Per-turn override trigger
Rec: Long-press (touch) / right-click (desktop) send → preset chooser → sets TurnOpts.AgentPresetID for that turn only.
Q7Session lock (subprocess-only)
Rec: Reuse the ADR-0018 model selector as a single routing selector: models + detected-only subprocess presets, mutually exclusive. Selecting a preset = lock (agent_preset_id ↔ clears model_id); drop route_agents.
Q8Marble model role on a routed turn
Rec: Emit subprocess result verbatim; no Marble model call (keeps cost savings real).
Q9Caps & concurrency
Rec: Reuse max_per_session, timeouts, max_output_bytes, stuck detection, process-group kill. No new caps.
Q10opencode + extensible driver registry
Rec: Add opencode driver (opencode run "…", verify flags at implement) + refactor driverFor() into a registry.
Q11Fallback when preset missing / disabled / not detected
Rec: Harness advisory + fall through to next priority (ultimately normal Marble turn). Never hard-crash.
Q12System agents
Rec: User sessions yes; system agents default off (same as ADR-0014 Q12).
Q13Agent tools for presets / routing
Rec: Agent may list/get presets + set session lock (mirror model_list/session_set_model); create/edit preset definitions are operator-only (Settings).

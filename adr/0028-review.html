Generic turn sinks — mirror every session response

When a session finishes a turn, hand the result to N configured sinks (Orb, Slack, ntfy, Discord, or a generic webhook) with a deep link back to the session. Orb is one built-in sink over a template-driven webhook base — the harness never learns what "Orb" or "Slack" is. Triggers off the existing session event stream; fire-and-forget; no recursion.

Core abstraction

type TurnEvent struct {
    SessionID, SessionTitle, Workspace, ModelID, TurnID string
    Kind       string   // complete | error | stop | cron | continuation
    Message    string   // final assistant text
    Preview    string   // first line
    DeepLink   string   // deep_link_base + "/s/" + SessionID
    Timestamp  time.Time
}

type Sink interface {
    Name() string
    Deliver(ctx context.Context, ev TurnEvent) error
}

Generic webhook sink

WebhookSink{
    URL, Method, Headers,
    Template   string,   // Go text/template over TurnEvent
    SecretEnv  string,   // env var name only
    Filters    Filters,
}
// orb / slack / ntfy / discord are constructors over this.
Why this is flexible: the deep link is a concept (TurnEvent.DeepLink), not an Orb field. Each sink projects it to its native mechanism — Orb X-Orb-Return-Url, Slack a button, ntfy a Click: header, Discord an embed url, a custom webhook {{.DeepLink}}.

deep_link_base is per-sink with a global default. For the Orb case today, that's https://<rinux-tailscale> so the notification links back to /s/{id}.

Secrets stay in ~/.marble/env; config references them by name (ADR-0016).

Reliability

non-blocking   enqueue → return; never wait on a sink
bounded queue  drop-with-log on overflow
idempotency    key = hash(sink, session, turn); pass through when sink supports it
retry          per-sink timeout + a couple jittered retries, then drop
no recursion   manager is harness code, never re-enters /api/prompt
coalesce       optional min_interval_sec per sink (off by default)

Session-level sink toggle (per-session override)

Not in Settings — this lives in the session view. Global enabled is the default; a session can force any sink on/off (or inherit) for itself only.

┌ Orb session · 0wdvhcj0q0 ──────────────────── [Sinks ▾] ─────────┐
│                                                                 │
│  ┌ Sinks for this session ───────────────────────────────┐      │
│  │  [ Pause all sinks ]   (sets every sink to off)       │      │
│  │                                                       │      │
│  │  orb      inherit ▾  · (global: on)                   │      │
│  │  slack    off      ▾  · (global: on)  ← overridden     │      │
│  │  debug    inherit ▾  · (global: off)                  │      │
│  │                                                       │      │
│  │  Changes apply to this session only.                  │      │
│  └───────────────────────────────────────────────────────┘      │
└─────────────────────────────────────────────────────────────────┘
Resolution: session override (on/off) wins; otherwise the global enabled; then filters still apply. "off · (global: on)" reads as “I muted this one session.”

Trigger & abstraction

Q1 How does the sink layer learn a turn ended?
Rec: Event-stream subscriber (not a named endTurn() hook).
Q2 Transport abstraction — generic webhook vs bespoke per channel?
Rec: webhook + template, built-ins on top.

Deep link

Q3 Deep-link auth — login-first vs expiring share token?
Rec: login-first (/s/{id}); share token later.
Q4 deep_link_base — per-sink or global only?
Rec: per-sink with a global default.

Secrets & rollout

Q5 How are sink credentials stored?
Rec: env-var name only (ADR-0016).
Q6 Which sinks ship first?
Rec: all six predefined types in M1 (webhook base makes them cheap).

Payload & filters

Q7 Payload — full final message or preview-only?
Rec: full message + first-line preview.
Q8 Tool-only turns — mirror or skip?
Rec: skip by default (no final prose = no mirror).
Q9 What filters does a sink get?
Rec: kinds + skip_empty + skip_cron + session regex + min_chars.

Delivery semantics

Q10 Coalesce bursts?
Rec: optional, off by default.
Q11 Delivery reliability contract?
Rec: at-least-once-in-process; idempotency key; bounded retry.

Config surface

Q12 Config surface for p1?
Locked (custom): Settings UI in first wave — not deferred. JSON + env secrets still canonical.

Per-session override

Q13 Per-session sink override — how does one session opt out of a global default?
Rec: inherit/on/off per sink + session popover + “pause all”.

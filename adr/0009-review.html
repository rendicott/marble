1. Goal

  • Built-in tools (all sessions)
  • Files under harness memory, not the project jail
  • Same process / port as Marble UI
  • Stable slugs for re-open after session close

Not this ADR

  • Auth / multi-tenant ACLs
  • Full site generator / media gallery
  • Version history of pubs
  • Replacing memory_write or session transcripts

2. Flow

user: research foo and mpub it → agent tools (grep, shell, …) → mpub_publish(slug="foo-research", title="…", content="## …") → write $MEMORY/mpub/foo-research/ → tool result: path=/mpub/foo-research url=http://127.0.0.1:8080/mpub/foo-research operator opens link in browser
mpub = human-facing pages. memory_write = agent long-term knowledge. Workspace files = code/config the agent edits for the project.

3. On-disk layout (proposed)

$MEMORY/mpub/
└── foo-research/
    ├── meta.json      # slug, title, session_id, times, content_type
    └── content.md     # body (or .html / .txt)

4. Tools (proposed)

ToolRole
mpub_publishCreate/update by slug
mpub_listList slugs + titles
mpub_getRead back for agent
mpub_unpublishDelete (Q11)

5. HTTP

GET /mpub              → index listing
GET /mpub/{slug}       → document (HTML shell for markdown)
GET /mpub/{slug}/raw   → optional raw body
Same unauthenticated trust model as the dashboard. If :8080 is reachable, pubs are too.

6. Implementation order (post-accept)

  1. internal/mpub store + slug rules + tests
  2. Tools wired into registry
  3. HTTP handlers (before SPA fallback)
  4. MD→simple HTML template
  5. System prompt blurb + docs

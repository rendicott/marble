Session management, history & memory

Persist sessions so Marble can be a long-lived general-purpose harness: sysadmin work, personal automation, and learning over time — not a chat that forgets on restart.

Date2026-07-16

1. Goal

Marble should support:

  • Sysadmin — durable run history across harness restarts
  • Personal automation — recall paths, decisions, routines
  • Learn over time — daily digests as the base layer for future memory tools

Separation of concerns

FlagRole
--workspaceAgent tool jail (read/write/list)
--memoryHarness private store (can be outside workspace)

Tools do not write into memory unless a future ADR adds intentional memory tools.

2. Short session IDs

Not GUIDs. Filesystem-safe, short enough to say out loud and put in filenames.

PartSizeNotes
Time prefix6 charsCrockford base32 · roughly sortable
Random4 chars~20 bits entropy
Total≈10 charse.g. k7m2q9a3f2
Current implementation uses 32-char hex — this ADR migrates to short ids for new sessions.

4. Background persist daemon

dirty sessions→ every 5 min→ write session/<id>.md→ clear dirty
  • Runs in-process inside marble-harness
  • Marks dirty on user / assistant / tool / title changes
  • No-op when nothing dirty
  • On shutdown: flush all dirty before exit
  • Errors logged + reflected on /api/health

Boot

  1. Index session/*.md for the left pane
  2. Selecting a session loads transcript into the live registry
  3. Closed sessions listed but not auto-active

5. Close session

UI: right-click session row → Close session

Rename…
Close session
Export…

Mobile: long-press menu (follow-up UX).

API:

POST /api/sessions/{id}/close
  1. Immediate flush to session/<id>.md
  2. Set status: closed, closed_at
  3. Drop from live agent registry (or inactive)

Does not wait for the 5-minute tick.

6. Daily compaction

RuleBehavior
Path daily/YYYY-MM-DD.md (host local calendar day)
When to run If any session activity that day; regenerate if newer than last digest
When to skip No new activity that day → no file, no rewrite
Content Per-session summary: goal, outcome, paths/tools — not full replay
v1 method Deterministic extract (title, first user, last assistant, tool names)
Later Optional LLM summarize via local model
Full fidelity always remains in session/*.md. Daily is the learning / skim layer.
